xv6-riscv · Overview

Five labs, one kernel

MIT 6.1810 gives each lab its own branch, tests and compile-time switch. I completed the first five labs and then merged them, so that every lab's features run in the same kernel.

C · RISC-V Jul – Aug 2026 Self-study

In short

Doing the labs one at a time was the easier part. The merge was harder, mainly because the page-table lab and the copy-on-write lab both change how physical pages are allocated and freed. I rebuilt the allocator so both could use it, then fixed the bugs that only appeared once all five labs ran together.

The details are in two separate pages: the allocator design and the debugging.

What each lab added

Dates are when I worked on each lab's branch. Everything listed is still enabled in the merged kernel. Click a lab to see the details.

  • util · Xv6 and Unix utilities Jul 1 Four user programs using existing system calls.
    • sleepSleeps for N timer ticks.
    • sixfiveReads a file and prints the numbers divisible by 5 or 6.
    • memdumpPrints raw memory according to a format string (int, pointer to string, inline string), so alignment and pointer indirection have to be handled correctly.
    • findRecursive directory search by file name.
  • syscall · system calls and a sandbox Jul 9 – 10 A syscall filter, and a program that reads stale memory.
    • interposeA per-process sandbox. sys_interpose() stores a 64-bit mask of blocked system calls and one allowed path in struct proc. syscall() checks the mask before dispatch, but still lets open and exec through when the path argument matches. Both values are inherited by fork().
    • attackRecovers another process's data from newly allocated pages. This is the reason kalloc() and kfree() normally fill pages with junk.
  • pgtbl · page tables and superpages Jul 26 – 29 The largest lab, and one side of the merge conflict.
    • vmprintPrints all three levels of an Sv39 page table. I used it for every later page-table bug.
    • usyscallMaps a read-only page into each process so ugetpid() can return the pid without a system call.
    • superpageMaps 2MB pages with level-1 leaf PTEs. mappages() got a page-size argument, and allocating, unmapping and splitting a superpage back into 4KB pages each needed their own code (uvmallocsuper(), uvmumsuper(), splitpage()).
    • dirtypagesWalks the page table for PTE_D and copies a bitmap, one bit per page, to user space.
  • traps · backtrace and alarms Aug 4 – 11 Reading and changing the state saved by a trap.
    • backtraceFollows the saved frame pointers (return address at fp-8, previous frame at fp-16) inside the current stack page. panic() calls it, so every later kernel panic prints a call chain.
    • sigalarm / sigreturnCalls a user handler every N ticks. The interrupted registers are saved in a separate handframe so sigreturn can restore them, and an in_handler flag stops the handler from being re-entered.
  • cow · copy-on-write fork Aug 7 – 19 The other side of the merge conflict.
    • cow forkfork() shares pages read-only instead of copying them. The original write permission is kept in the spare PTE_RSW bit, so the page-fault handler can tell a COW page from a page that was always read-only.
    • refcountingEach physical page has a reference count, so a shared page is freed only once. This has to work for 4KB pages and 2MB superpages, which is where this lab conflicts with pgtbl.

Merging the labs

I merged the branches one at a time between Aug 9 and Aug 19. The first three merges brought bugs (attack, memdump, sbrkmuch) but no design conflict. The COW merge was different, because superpages and reference counting needed the allocator to work in two incompatible ways.

What the merge required

Removing the LAB_* switches

Each lab wraps its code in #ifdef LAB_PGTBL-style guards, so one build contains only one lab. I removed them all except LAB_SYSCALL. The attack exercise only works if kalloc() and kfree() do not fill freed pages with junk, while the other labs expect the junk fill. The two requirements conflict, so I kept the switch instead of choosing one.

Re-checking every lab after each change

A merge can break a feature that already worked. The traps merge, for example, broke usertests sbrkmuch and lazy allocation. I added one make target that rebuilds the kernel and runs every lab's tests, and ran it after every fix to confirm that all five labs' features still worked together.

Marking which lab owns which code

Once five labs edit the same files, it is hard to tell which lab a line belongs to. Every block I added has a searchable comment such as pgtbl_part:superpage, cow_part:cow, memory_part:buddy or sbrk:flag, so a feature's code can be found with grep.

Even after the merge was finished, usertests still failed in some cases. The causes included alarm fields that were not cleared when a process slot was reused, a sandbox path copied across fork() without its null terminator, a syscall mask too small for syscall numbers above 31, and a COW page freed with the wrong page size. Each of these was correct while only one lab used the code. They are described in the debugging page.

Next steps

Four labs remain: networking, locks, file system and mmap. I plan to do them in order and merge each one before starting the next.

The locks lab is directly related to this project. The allocator currently uses one global lock, which made the merge easier to get right. Per-CPU free lists are the obvious next step once the rest of the kernel is stable.
