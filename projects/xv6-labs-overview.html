xv6-riscv · Overview

Five labs, one kernel

MIT 6.1810 ships each lab as its own branch, each with its own test suite, each guarded by its own compile-time macro. Passing five of them separately is the assignment. Getting all five to run in one kernel at the same time is a different problem — and the more interesting one.

C · RISC-V (Sv39) QEMU · GDB Jul – Aug 2026 Self-study, ongoing

In short

I worked through the first five 6.1810 labs on separate branches — utilities, system calls, traps, page tables, and copy-on-write fork — then merged all five into one kernel where every lab's features are live at the same time, rather than five checkouts that each work in isolation.

The merge is where the real work was. Two labs had independently taken ownership of the same thing: the page-table lab wanted the allocator to hand out 2MB superpages, and the COW lab wanted every frame to carry a reference count. Reconciling them meant rebuilding the physical memory allocator, which is written up separately in the allocator deep dive, along with what broke while getting there.

01 · The labs

What each branch added

Each lab is listed with what actually got built, and dated by when the work happened on its own branch — not by when it was merged. Every feature below is live in the merged kernel. Open a lab for the detail.

  • util — Xv6 and Unix utilities Jul 1 Four user-space programs written against the existing syscall surface.
    • sleepBlocks for N ticks — the smallest possible round trip through the syscall path.
    • sixfiveStreams a file byte by byte, parses integers out of it, and prints the ones divisible by 5 or 6.
    • memdumpA format-string-driven memory dumper: given a spec like "ii", "s" or "S", it decodes raw bytes as ints, pointers-to-string, or inline strings — which forces you to reason about layout, alignment and indirection rather than just printing.
    • findRecursive directory walk with name matching, on xv6's own file-system API.
  • syscall — system calls and a sandbox Jul 9 – 10 Kernel-side syscall machinery — then a program that attacks it.
    • interposeA per-process sandbox: sys_interpose() takes a 64-bit reject mask plus one allowed path, stored in struct proc. A central check in syscall() rejects any masked call before dispatch, with a carve-out that lets open and exec through when their first string argument matches the allowed path. Both the mask and the path have to survive fork().
    • attackRecovers another process's data out of freshly allocated pages — the concrete demonstration of why kalloc() and kfree() fill memory with junk in the first place.
  • pgtbl — page tables and superpages Jul 26 – 29 The heaviest lab, and the origin of half the merge conflict.
    • vmprintRecursive page-table printer across all three Sv39 levels — the tool that makes every later page-table bug inspectable.
    • usyscallA read-only page shared with each process so ugetpid() can read its own pid without trapping into the kernel at all.
    • superpage2MB leaf PTEs at level 1: mappages() gained a granularity argument, and allocation, unmapping and in-place demotion each needed a superpage-aware path (uvmallocsuper(), uvmumsuper(), splitpage()).
    • dirtypagesReports which of a process's pages are dirty by walking the table for PTE_D and packing the result into a bitmap — 64 pages per 64-bit word — then copyout()ing it to user space.
  • traps — backtraces and user-level alarms Aug 4 – 11 Reading and rewriting the machine state a trap leaves behind.
    • backtraceWalks the saved frame-pointer chain — return address at fp-8, caller's frame at fp-16 — bounded by the stack page, and wired into panic() so every later kernel panic prints its own call chain.
    • sigalarm / sigreturnPeriodic user-level handlers driven by timer ticks. The saved user context lives in a separate handframe so the handler can return to exactly where it interrupted, with an in_handler flag guarding against re-entry while a handler is still running.
  • cow — copy-on-write fork Aug 7 – 19 The other half of the merge conflict — and the branch the allocator was rebuilt on.
    • cow forkfork() stops duplicating memory: parent and child share frames read-only, with the original writability parked in a spare PTE bit (PTE_RSW) so the write-fault handler can tell a COW page from a genuinely read-only one.
    • refcountingEvery physical frame carries a reference count, so a shared page is returned to the pool exactly once — at 4KB or 2MB granularity, which is precisely where this lab collides with pgtbl.
    • allocatorThe later commits on this branch are the allocator rebuild itself: a single reference-counted structure serving both page sizes. That is its own write-up.

02 · The merge

What it cost to make five labs one kernel

Four sequential merges over eleven days. The first three were mostly mechanical. The last one was not, because it is where two labs' claims on physical memory had to be settled.

Three things the merge actually required

Deleting the LAB_* compile-time macros

The labs ship behind #ifdef LAB_PGTBL-style guards, so one checkout serves one lab. A kernel that does all five at once cannot be built that way, so the guards came out. One was kept deliberately: LAB_SYSCALL, because the attack exercise only works while kalloc()/kfree() are not scrubbing freed pages — a real conflict between two labs' requirements, resolved by keeping the switch rather than silently picking a side.

Re-checking all five labs' features after every change

Merged code breaks features that used to work — the traps merge, for instance, arrived with usertests sbrkmuch and lazy allocation failing. Each lab has its own test suite, and usertests exists to find out whether the kernel has been broken, so re-running all five together after every change is what makes "merged" mean something stronger than "compiles" — which also meant fixing the build rules so they can all run in one pass.

Making the merged code navigable

Once five labs share the same files, "which lab does this line belong to?" becomes a real question. Every non-stock block carries a searchable keyword comment — pgtbl_part:superpage, cow_part:cow, memory_part:buddy, sbrk:flag — so any feature's implementation is one grep away instead of a diff archaeology exercise.

And the merge kept producing bugs after it was "done". The last commits exist because usertests failed under specific conditions once all five labs' state lived in the same kernel: alarm-handler fields surviving process reuse, a sandbox path copied across fork() without its terminator, a reject mask too narrow for the syscall numbers it had to hold, and a copy-on-write frame freed at the wrong granularity. Every one of them was correct while a single lab owned it — which is exactly the class of bug a merged kernel produces and a single lab cannot. Those are written up here.

03 · Next

Still open

Four labs remain, and I am taking them in order — one lab, then one merge, then the next. Networking is next, followed by locks, the file system, and mmap.

The locks lab is the one this project is already pointed at, because per-CPU free lists are exactly the trade-off the current allocator deliberately declined to make: a single global lock was the right call for getting the merge correct, and it is the first thing that should change once correctness is no longer the scarce resource.
